## เครื่องมือและเกณฑ์ (อ้างอิงคู่มือกรมสุขภาพจิต/สพฐ. ฉบับไทย)
- **2Q** — เดิม (นักเรียนทำเองอิสระ ไม่จำกัดรอบ) ไม่เปลี่ยนข้อความคำถาม; แก้เฉพาะข้อความผลที่นักเรียนเห็นจาก "ทำ PHQ-9 ต่อ" เป็นข้อความกลางๆ
- **9Q** (แทน PHQ-9 สากล) — 9 ข้อ ข้อละ 0-3; รวม <7 ไม่มีอาการ/น้อยมาก, 7-12 น้อย, 13-18 ปานกลาง, ≥19 รุนแรง; **ธงแดง = ข้อ 9 > 0** (แยกจากคะแนนรวม)
- **8Q** — คะแนนไม่เท่ากันต่อข้อ (1,2,6,8,9,4,10,4) ข้อ 3 ถ้า "มี" ถามต่อควบคุมได้ไหม (ได้ +0 / ไม่ได้ +8); 0 ไม่มี, 1-8 น้อย, 9-16 กลาง, ≥17 รุนแรง = ส่งต่อโรงพยาบาลด่วน

## สิ่งที่บังคับที่ firestore.rules (ไม่ใช่แค่ซ่อนปุ่ม)
| | ครูแนะแนว | ครูที่ปรึกษา (ห้องนั้น) | นักเรียน | ผู้บริหาร |
|---|---|---|---|---|
| 2Q | อ่าน/เขียน | อ่าน/เขียน | อ่าน/เขียนของตัวเอง (ไม่จำกัดรอบ) | อ่าน (นับรวม) |
| 9Q ระดับ + ธงแดง (`student_screenings_9q`) | เต็ม | อ่านเสมอ | ห้าม | ห้าม |
| 9Q คำตอบ/คะแนนดิบ (`..._9q_detail`) | เต็ม | อ่านได้เฉพาะเมื่อ **ไม่มี**ครูแนะแนวที่ใช้งานอยู่ | ห้าม | ห้าม |
| 8Q คะแนน/คำตอบ (`student_screenings_8q`) | เขียน+อ่าน | เขียน+อ่านเฉพาะเมื่อไม่มีครูแนะแนว | ห้าม | ห้าม |
| 8Q "มีเคส ใช่/ไม่" (`student_8q_case_flags`) | เขียน+อ่าน | อ่านเสมอ | ห้าม | ห้าม |
- **9Q (summary / detail / progress): client เขียนไม่ได้เลย** (`allow write: if false` — แม้ครูแนะแนว/SUPER_ADMIN) เขียนผ่าน callable `submitNineQ` เท่านั้น (ดู "แก้แล้ว" ข้อ 2)
- นักเรียนทำ 9Q ได้เมื่อ**เซิร์ฟเวอร์**พบ **ฐาน (basis) ที่ยังไม่เคยใช้**: 2Q ล่าสุดบวก (basisId = id ของ 2Q ฉบับนั้น) หรือใบอนุญาต (grant) ที่ครูเปิดให้ — ฐานหนึ่งใช้ได้ครั้งเดียว (`usedBasisIds` append-only เขียนใน transaction เดียวกับผล)
- **8Q บันทึกได้เสมอ** (ครูแนะแนว; ครูที่ปรึกษาเมื่อไม่มีครูแนะแนว) ไม่ต้องมี 9Q ≥7/ธงแดงมาก่อน — เงื่อนไขนั้นเป็นแค่เหตุผลที่ระบบ "แนะนำ" (SUPER_ADMIN แก้ข้อมูลได้เช่นกัน); rules คำนวณคะแนน/ระดับ/ส่งต่อด่วนของ 8Q ซ้ำจากคำตอบดิบเอง
- `hasActiveGuidanceCounselor()` ใน rules อ่าน cache `school_settings/guidance_status` (client เขียนไม่ได้แม้ SUPER_ADMIN) ที่ Cloud Functions คำนวณ

## จุดที่ตัดสินใจเอง (สเปคไม่ชัด) — โปรดตรวจ
1. **แยกข้อมูลหลาย collection** เพราะ Firestore ไม่มีสิทธิ์ระดับ field — จึงเกิด `student_screenings_9q` (สรุป) / `_9q_detail` / `_8q` / `student_8q_case_flags` / `student_screening_progress` (+ `grants`) / `student_screening_notices`
2. **ธงแดงข้อ 9 อยู่ในเอกสารสรุป** ที่ครูที่ปรึกษาอ่านได้เสมอ (สเปคบอกครูที่ปรึกษาเห็น "แค่ riskLevel" — แต่การเปิด 8Q และคำเตือนแจ้งผู้ปกครองต้องรู้ธงแดง)
3. **"ล่าสุด" = เอกสารเดียวต่อนักเรียน เขียนทับ** (เหมือน 2Q/PHQ-9 เดิม) → ดู TODO ประวัติด้านล่าง
4. **ครูที่ปรึกษา**เปิดใบอนุญาต 9Q ได้เสมอ แต่ **กรอก 9Q แทนนักเรียนได้เฉพาะเมื่อไม่มีครูแนะแนวที่ใช้งานอยู่** (สเปค TODO-5: "ครูที่ปรึกษา กรณีไม่มีครูแนะแนว"); เซิร์ฟเวอร์บังคับด้วย `decideNineQCaller` — มีครูแนะแนวหรือสถานะไม่ทราบ = ปฏิเสธ
5. **SUPER_ADMIN** อ่าน/เขียนได้ทุกชั้น (ตามแนวเดิมของ collection อ่อนไหวอื่น เช่น `guidance_counseling_cases`) — ตารางสเปคไม่ได้พูดถึง
6. **EXECUTIVE**: อ่าน 2Q ได้เหมือนเดิม (นับรวม) แต่ **อ่าน 9Q/8Q ไม่ได้** และการ์ด PHQ-9 ในหน้าผู้บริหารถูกแทนด้วยข้อความ "ไม่เปิดให้ผู้บริหาร" (สเปคไม่ได้ระบุผู้บริหาร)
7. **PHQ-9 เดิม**: collection `student_screenings_phq9` เก็บไว้ อ่านได้เฉพาะครูแนะแนว/แอดมิน ห้ามเขียน ไม่แสดงใน UI — ข้อมูลเก่าไม่ถูกแปลงเป็น 9Q (คนละเครื่องมือ)
8. **ใครแจ้งผู้ปกครองเรื่อง 8Q ได้**: ครูแนะแนวเสมอ; ครูที่ปรึกษาเฉพาะเมื่อไม่มีครูแนะแนว; 9Q: ทั้งสองฝ่าย
9. **วิธีแจ้งผู้ปกครอง** (สเปคไม่ระบุตัวเลือก): โทรศัพท์ / พบด้วยตนเอง / ข้อความ (เช่น LINE) / อื่นๆ — แก้ที่ `PARENT_NOTICE_METHOD_LABEL`
10. **"มีเคสอยู่ในการดูแล" = 8Q ที่บันทึกล่าสุดมีคะแนน > 0**
11. **ครูที่ปรึกษา "ของห้องนั้น"** เทียบ `students.room` กับ `staff.assignments.homeroomClass` แบบตรงตัวเหมือน rules อื่นของระบบ (ไม่ใช้ `isSameRoom`) — ห้องที่เขียนต่างฟอร์แมต (`ม.5/8` vs `M.5/8`) จะไม่ตรง
12. ครูที่ปรึกษาโหลดข้อมูลรายคน (`getDoc`) ไม่ใช่ live — กดทำรายการแล้วโหลดใหม่เอง (rules ผูกห้องต่อเอกสาร list ทั้ง collection ไม่ได้)
13. **ข้อความผล 2Q ที่นักเรียนเห็น**: "พบความเสี่ยงเบื้องต้น — ครูแนะแนวหรือครูที่ปรึกษาอาจชวนพูดคุยเพิ่มเติม หากรู้สึกไม่ไหว บอกครูที่ไว้ใจได้ทันที" (ไม่ได้ใส่เบอร์สายด่วน เพราะสเปคไม่ระบุ)
14. ข้อความคำถาม 9Q/8Q ใช้ตามสเปคตัวต่อตัว **ไม่ได้เติมกรอบเวลา** (เช่น "ในช่วง 2 สัปดาห์ที่ผ่านมา") ที่หัวฟอร์มเพราะสเปคไม่ระบุ
